# Phase UI (F5–F8, C3–C5, A5: design system, storefront and login) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the approved Aarvion design system and prototypes into the Next.js app, in 34 PRs. It delivers:
- the design tokens, self-hosted fonts and base components;
- overlay, form, OTP and toast primitives;
- the layout shell, error pages and legal pages;
- the home page with its 5-act scroll film;
- the category, product and search surfaces;
- the OTP login page and header dialog.

Every price comes from real catalogue data through tagged, cached server queries.

**Architecture:**
- **Rendering.** Cache Components is on (`cacheComponents: true`). Pages are static and prerendered from the DB at build time. All catalogue reads go through `'use cache'` wrappers in `src/lib/catalogue/cached.ts`, tagged `catalogue`. `revalidateCatalogue()` expires that tag with no stale window, so an MRP edit is visible on the next request.
- **Styling.** Tailwind 4 `@theme` carries `design/prototype/css/tokens.css` verbatim. The world's component CSS (pocket, strip, stamp, film, auth) is ported from `site.css`/`flows.css` as plain CSS files in `@layer components`, keeping the prototype class names. That keeps every rule diffable against the prototype and lets the film engine keep its selectors. Tailwind utilities are used for new layouts.
- **Client islands.** Client code is limited to the nav, search, cart controls, toast, film engine and login.
  - The scroll film is a faithful TypeScript port of `design/prototype/js/site.js`: one passive scroll listener, one rAF tick, transform/opacity only, and a static composition under reduced motion. Its pure progress, geometry and dot math is unit-tested.
  - Search and login dialogs are imported on first open, to hold first-load JS ≤ 150 KB.
  - Auth state is fetched after hydration, so the header stays static.

**Tech Stack:** Next.js 16.4 App Router (Cache Components, `next/font/local`, `next/image` AVIF), React 19.3, TypeScript 6.0 strict, Tailwind CSS 4 (`@tailwindcss/postcss`), shadcn/ui (`dialog`, `input-otp` only; Radix Dialog underneath), `subset-font` + `fontkit` (font subsetting and coverage tests), Vitest 5 (`unit` node, `ui` happy-dom + Testing Library, `int` MongoMemoryReplSet), Playwright 1.65 (Chromium; also drives `scripts/shoot.mjs`), GitHub Actions.

## Decisions taken in this plan (rulings; override any)

**Rendering and caching**
- **Cache Components.** `cacheComponents: true` is required for `'use cache'` + `cacheTag`.
  - Cost: `export const dynamic` is removed from the 6 existing route files. GET handlers call `await connection()` instead.
  - Int tests mock `next/server` `connection` and `next/cache` through `tests/helpers/next-mocks.ts`.
- **Build-time data.** With Cache Components, `generateStaticParams` must return at least one param, so `next build` needs a seeded DB.
  - The CI `build` job gets `pnpm db:up && pnpm db:indexes && pnpm seed` (`MONGODB_DB=aarvion_build`), and the `e2e` job adds `pnpm seed`.
  - Vercel builds read their own environment's DB.
- **Freshness over speed for prices.** `revalidateCatalogue()` calls `revalidateTag("catalogue", { expire: 0 })`, not `"max"`. The first request after an edit waits for a fresh render instead of showing the old MRP.
  - `cacheLife("hours")` is a backstop for writes that bypass `revalidateCatalogue()`.
  - Phase D's MRP, photo and status edits must call `revalidateCatalogue()`.
  - `POST /dev/catalogue/revalidate` exists for e2e.
- **Header auth state** is fetched after hydration from a new `GET /api/auth/session`. It always returns 200, with `{ user }` or `{ user: null }`.
  - This keeps every page static, and avoids a 401 console error per guest page from `/me`.
- **Copyright year** is the constant `SITE_CONFIG.copyrightYear = 2026`; server components may not call `new Date()`.

**Design-system port**
- **CSS.** The ported CSS keeps the prototype class names, in plain CSS files under `@layer components`. Tailwind utilities can override them, and the film keeps its selectors. It is not rewritten as utilities.
- **Fonts: `next/font/local` with committed subsets, not `next/font/google`.** Google's `latin` subset lacks ₹.
  - `scripts/subset-fonts.ts` (harfbuzz via `subset-font`) cuts Basic Latin, Latin-1, the punctuation the copy uses, `₹` and `→`.
  - Axes are trimmed to the loaded weights: Host Grotesk 600–700, Geist 400–600, Geist Mono 500–600.
  - Montserrat is a static 800 instance holding only `AARVIONPHMCEUTLS`, until the wordmark is outlined.
  - Sources: Geist from the `geist` npm package; Host Grotesk and Montserrat TTFs from `github.com/google/fonts` (OFL), committed with licences and SHA-256s.
- **shadcn.** Only `dialog` and `input-otp` are generated.
  - The Sheet is the `side` variant of the same Radix Dialog; shadcn's `sheet.tsx` would duplicate that primitive.
  - In generated files, the `lucide-react` icon import is replaced with our `Icon`, so there is no icon-library dependency. `tw-animate-css` is not installed; overlay motion is our own keyframes.
- **Toast.** The customer toast is our own small component (one toast at a time, 4.6 s, pause and resume), not Sonner. It saves first-load JS and the spec needs no more.
- **Styleguide route.** `/styleguide` lives at **`/dev/styleguide`**, because of the existing dev-route convention and its `requireDevRoute()` test. It is a 404 in production, and available in dev, preview and e2e builds.
- **Danger colours.** One danger scale: the customer `danger` tokens. The admin reds wait for phase D (DESIGN.md flags the drift).
- **Icons** are inline SVG components holding the prototype sprite's path data. There is no sprite and no icon package.
- **Prototype conveniences dropped.**
  - Switching every lazy image to eager 300 ms after load is dropped (it wastes 4G data); each act eager-loads and decodes its images when it comes within one viewport.
  - `?demo=states` is dropped. `?p=<act>:<progress>` is kept: it is harmless and lets review frames be captured.

**Content and claims**
- **Country of origin** is "India" when the manufacturer address contains an Indian PIN (`\b[1-9]\d{5}\b`) or a marker from `INDIAN_ADDRESS_MARKERS = ["Haridwar", "Uttarakhand", "(HP)", "Himachal", "(Pb.)", "Punjab", "Delhi"]`; otherwise it is "To be added".
  - All 9 manufacturers on file resolve to India. Hyloage and Sysnet (no manufacturer) show "To be added" for both manufacturer and origin.
- **Product information sections** (uses, how it works, storage, precautions) are omitted. No source copy exists, and inventing it risks therapeutic claims. They need owner-supplied copy that has been legally reviewed.
- **Win2Age photos.** Product pages with `imageSource: "win2age"` carry the caption "Photo shows the pack printed under Win2Age Pharma, Aarvion’s earlier marketing name." (from the FAQ).
- **Legal timelines.**
  - Facts not in `requirements.md` render "To be added": grievance response times, data storage location, retention periods, delivery times, governing law, customer-care contact, licence, pharmacist and GSTIN details.
  - The accepted proposals (returns reported within 48 h of delivery; refunds to source in 5–7 working days) are stated.
- **Consent at sign-up.**
  - The prototype's implied sentence ("By creating an account you agree…") becomes a **required checkbox**: "I agree to the Terms of use and the Privacy policy". DPDP needs a clear affirmative action.
  - "I am 18 or older" is required.
  - Marketing is optional and off by default.
  - The consent version is `POLICY_VERSION = "2026-11-17"`, which is also the legal pages' "Last updated" date.
- **Dropped until K1:** "Your cart stays as it is when you sign in", because the guest-cart merge is not built yet.
- **Catalogue order.** Families are ordered by the DB `sortOrder`; within a family, by the leading variant number (as `getFamily`). Cardiology therefore reads Bemptor-180, Bemptor-R40, Sacuwin 50/100/200, not the prototype's Sacuwin-first order. The admin owns the order.
- **Counts in copy come from data:** "All 11 medicines", "Eleven medicines…". "Every one needs a valid prescription" appears only while every listed product has `rxRequired`.
- **JSON-LD** omits `availability`, ratings and reviews, because stock is not tracked and none of those exist.
- **Robots.** `robots.ts` disallows everything unless `VERCEL_ENV === "production"`.

**Flows and routes**
- **Pending routes.** `/cart`, `/account` and `/account/prescriptions` are linked now, at their final URLs, and so are the four live `/category/*` pages until Task 24. They are listed in `PENDING_ROUTES`, and the e2e link check expects them to 404 until the task that builds each one (Task 24, K2, P1, R3) removes it from the list.
- **Pockets link to product pages.** The prototype has no product page, so its pockets do not link. From Task 25, the name in each catalogue and feature pocket links to `/product/<slug>`; otherwise product pages would be reachable only from search. Hero pockets stay buttons.
- **Cart.** A session-only UI store (`sessionStorage`; caps of 10 per product and 20 packs per order) drives the pocket and product cart controls and the nav count until K2 replaces its persistence behind the same hook.
- **Upload Rx** pills and CTAs link to `/account/prescriptions` (R3).
- **Home nav** follows the prototype: no account pill; the search icon appears at ≤ 880 px and focuses the hero search. Site pages add the account pill and the search dialog button.
- **Sign-up on verify.**
  - When verify is called for an unknown identifier with the right code and no `signup` field, it answers **409 `signup_required`**, creates nothing and leaves the challenge unconsumed. The correct check refunds its attempt.
  - The profile step then resends the code with `signup`.
  - Wrong codes still spend attempts and get 400 `invalid_code`, so account existence never leaks without the code.
- **Tries left.** The client counts tries left (5, pinned to `OTP_MAX_ATTEMPTS` by a test); the server does not return the count. The 24 h server cap (429) shows a separate locked message.
- **Login demo states.** `?state=otp-sent|otp-error|otp-locked|new-account` exists for review captures, and only when `!isMockForbidden()` (computed on the server at build).
- **Search.**
  - `GET /api/products?q=` filters the cached catalogue in memory with the server's `matchesTokens`.
  - Limits: 60 requests per minute per IP bucket; `q` longer than 64 characters gets 400 `query_too_long`; results are capped at 20.
  - No CDN caching, because prices must be fresh.
  - The hero search uses the same matcher on the client. A `/search` results page is out of scope here.
- **JS budget.** The search and login dialogs are dynamically imported on first open.
