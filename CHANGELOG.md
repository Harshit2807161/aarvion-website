# Changelog

All notable changes to the Aarvion storefront are recorded here, newest first.

The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and the
version in `package.json` follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Every PR adds one line under `[Unreleased]`**, in the right section (Added, Changed,
Deprecated, Removed, Fixed or Security). Write it for the next maintainer, say what changed and
where, and end it with the PR number, for example `(#57)`. If the number is not known yet, add it
in a follow-up commit after `gh pr create`. Group Dependabot bumps into one line per release.
List only sections that have entries.

Release dates are in IST (Asia/Kolkata). Versions are not tagged yet, so the compare links at the
bottom use commit SHAs.

## [Unreleased]

### Added
- `finishRxUpload` now leases its staging slot (`claimStaging` and `releaseStaging` in `src/server/prescriptions/prescriptions.ts`, 30 s, a `claimedUntil` field that a crashed claim simply outlives), so one start again bounds the re-encode and final-put work: a concurrent or repeat finish gets a retryable `busy`, a refusal consumes the slot, and `busy` or an abort releases the lease. After an unknown commit result it reads the record back (default read concern, on purpose) and returns ok if it committed; otherwise the final file is kept and the error rethrown (#214).
- `finishRxUpload` (`src/server/prescriptions/upload.ts`): peeks the staging slot, reads and checks the staged file through `checkRxFile` (images re-encoded, PDFs stored unchanged), stores it privately at `rx/<uid>/<rxId>.<ext>`, then in one majority-concern Mongo transaction takes the slot, inserts a `pending` record and appends the `rx.upload` audit row (ids and flags only; the caller's role is recorded), so a record never exists without its audit and a failed attempt retries on the same slot. A `busy` PDF check keeps the staged file for a retry; if the commit's outcome is unknown the final file is always kept and the error rethrown (the sweep removes an orphan); a put that already landed with the same SHA-256 counts as success; the staged file is deleted best-effort. `appendAudit` takes an optional session (#211).
- Phase O plan `docs/superpowers/plans/2026-11-28-phase-o-orders-payments.md` (21 tasks O1–O21: order rules, order store with transactions, address book, gateway contract with a Mongo-backed fake, Razorpay adapter and a `none` gateway, idempotent COD and prepaid placement, refunds, payment capture and verify, the deduplicated webhook, the reconcile cron, checkout, order pages and e2e), its provisional rulings in `docs/decisions/rulings.md` ("Phase O plan") and the handoff pointer (#216)
